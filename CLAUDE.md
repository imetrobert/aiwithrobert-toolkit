# toolkit.aiwithrobert.com — working guide

Private admin tool for AI with Robert (client-session materials, feasibility check, Leads pipeline, site availability, surveys).
ONE static file: `index.html` (~400 KB: CSS in the first ~190 lines, then one `<script>` with the whole app). No build step, no AI API
calls (AI steps are copy/paste into free chatbots; only the survey photo reader can use an optional Gemini key kept in the browser).
Repo: imetrobert/aiwithrobert-toolkit; sign-in via the shared Supabase project, app `toolkit` in imetrobert/Supabase-platform-.

## NEVER read index.html whole

Open `docs/code-map.md` first (generated by CI on every push: line numbers of every screen, constant and function), then read only the
range you need with an offset/limit or `grep -n "name" index.html`. Edit recipes for the likely changes are in `docs/common-edits.md`.
Style helpers: `el()` builds DOM, `S` is the state object, `render()` redraws, `sbReq()` calls Supabase, `Store`/`Cloud` keep sessions.

## Hard rules

- New Supabase table or migration: put explicit Data API grants in the SAME file (copy `migration/site_capacity.sql`). Migrations are run by hand
  in the Supabase SQL editor before deploying; `scripts/check_toolkit.py` fails if a migration creates a table without grants.
- Prices live in `FX_PRICE`; keep equal to the Pricing section on biz.aiwithrobert.com (+ llms.txt) and `BUSINESS_SERVICES` in the invoicing app.
- No emoji in client-facing outputs. Info/warning/error message colours stay neutral (grey info, burnt-orange warning, red error), never a brand colour.
- Seniors outputs use the Seniors brand; Business outputs use the Business brand (navy + gold); the safety box is red in Business outputs.
- Wording for seniors says "bookings", not "students". Every output has an EN and FR version where the output language is chosen; the interface is English only.
- A phone that opened the app from the Home Screen icon may show a stale version; a Safari reload shows the new one.

## Checks and automation (GitHub Actions: Maintain)

`python3 scripts/check_toolkit.py` (JavaScript syntax of the app, migration grants, FX_PRICE and booking link equal the Business site) and
`python3 scripts/code_map.py` run on every push to `main` that touches `index.html`, `migration/` or `scripts/`, and weekly. A red run means something
drifted (usually a price). The same workflow commits the refreshed `docs/code-map.md`.
